## Roles and stop conditions

The installer learns and prepares; the owner appoints; the appointed host retains its own private key; the door enforces policy. The installer never requests/receives that private key. ChatGPT/Gemini, the new native Sidekick/WordPress Agent drafts and the aligned Grok Bot/Muse drafts do not offer the current session as a lasting host: that path is blocked without isolated recoverable custody, and the useful planning draft is preserved. Muse’s disclosed possible future low-risk/mock custody boundary does not pass the stronger isolated production gate. Any same-agent possibility still needs explicit appointment, a separate host key, naming and verified recovery; its role/custody design remains unsettled. Chief of Staff remains steward, not automatically Suzu. Host and visitor keys are always different in these recipes.

Every recipe distinguishes conversation/draft, staged setup, installed/validated and blocked. These are statuses to prove, not modes that reading the file activates. In the ChatGPT/Gemini Draft 4 and new native drafts, staged means prepared for nonpublic testing; signed, appointed, deployed, validated and publicly open are independently evidenced, with no status implying another. No complete setup can be claimed without its real integrations. The supported signing origin is https://sign.kigenka.com; preferred approval-link/results and disclosed ask-first signed-file upload are supported directions, not proof this host-card flow works. The signed-JSON download/re-upload fallback is last-resort and disclosed before starting, without asking owners to edit JSON. A return-to-assistant/authorized-destination status-check replacement is desired but not built; no signing-page-to-door dispatch is claimed. ## Important unresolved integration and signed-content boundaries

The package’s documented manual `shokai init` generates a project-local private key. That is **not** a validated appointed-host key handoff. These drafts stop before a guide-local key-generation/adoption step; they do not invent import flags, a hosted signer or a secret transfer. The installer can draft without the host key, but cannot declare the full appointment/door integration complete until a compatible custody path exists.

Separate room/media/service decor lives at the place, outside the signed house digest. The older broad “house config includes all presentation” note and the later decor lesson are reconciled by this explicit boundary, not by weakening signatures.

Still open: default door hosting (ours or merchant server); exact Shopify/WooCommerce permissions; real-store proposal/draft mapping; live doorbell to the appointed agent (including ChatGPT, Gemini, Sidekick, WordPress Agent, Grok Bot or Muse); hosted key home; same-agent lifecycle; the exact leaflet addition and trusted visitor-skill URL.
