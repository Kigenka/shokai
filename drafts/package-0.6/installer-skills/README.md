## Shared addition (18 November 2026): naming the host representative

`INVITATION-SETUP.md` is a new shared chapter: when the owner wants to send invitations or hold an event, the host walks them through who it is for, what is offered inside, and how long a hold and the owner's approval stay open (24 hours by default, set as an invitation parameter, `hold_hours`). The visit does not wait on the passkey; the guest may leave with the pack and the item on hold, and when the owner taps later the order completes and the receipt updates without the guest returning. Only the passkey places the order.

`NAMING-THE-HOST.md` is a new shared chapter, linked from every installer draft: naming the host representative is a required setup step. The installer asks the owner what their host should be called, offers a few fitting suggestions in the place’s spirit, and lets the host suggest a name of its own; the owner confirms. The confirmed name is written into `LOUNGE_HOST_NAME` or the equivalent host-name config, the host agent’s own name, and the invitation line, and into the host card’s role or appointment text when that text includes the calling name. A named host representative is the place’s personality, not just a bot. A lesson from the Lounge: a hand setup skipped this step and missed a chance to test the installer; setups should run the installer skill.

## Shared addition (18 November 2026): appointing the host (signing the card)

`APPOINTING-THE-HOST.md` is a new shared chapter, linked from every installer draft: signing the host card is a required setup step and the heart of setting up a place. It is the owner's contract with the appointed host representative. The order is: name the host, prepare the card (role, duties, place, door, relying-party id, about 90 days), the owner reviews and taps their passkey, then the card is hung on that door and the door is redeployed. One signed card per door, including a room or shop with a door of its own. Signing does not open the door or charge anyone. Until a door has its card, it honestly says it is not open, and the host checks before sending a guest there. A later change to the role text or the calling name needs a new passkey signature.
